This replaces round 1's `bugs-and-risks.md`. It's measured against your goal: **self-hosted, private, less buggy, and usable offline on game day**.

**What I did this time:** read every non-boilerplate source file, installed dependencies, and ran the tests, typecheck, lint, production build and dependency audit. I ran the built app in a headless browser to watch what it actually does on load, through the tutorial (desktop and phone width), and with a Swiss zone question. I also queried the public map-data (Overpass) servers directly about Swiss boundaries.

**How sure each finding is:**

- **Seen running:** I watched it happen in the built app or a command.
- **From code:** clear from reading the code, but not reproduced.
- **Likely:** probably true; needs a check.

**Correction from round 1:** I said the question caches were keyed by object identity and would go stale on every edit. That was wrong. They do have content-based keys ([matching.ts:247](../src/maps/questions/matching.ts#L247), [measuring.ts:322](../src/maps/questions/measuring.ts#L322)). The real cache problems are narrower; see B9.

## C. Questions that make no sense in Switzerland as written

Not bugs, but they matter for your games:

- **Major city** means population of 1,000,000 or more. Switzerland has none (Zürich is about 0.4M), so the question can never match.
- **Coastline:** Switzerland is landlocked. The question still downloads a 4 MB world coastline file.
- **7-Eleven:** probably none in Switzerland. McDonald's works.
- **High-speed rail** is named "shinkansen" internally and relies on `highspeed=yes` tags. Swiss coverage is thin; this needs checking against your rules.
- **Large countrywide queries:** "-full" (small/medium game) variants refuse to run above 1000 results. Parks and mountain peaks will likely exceed that across Switzerland. I couldn't get exact counts because all three public servers failed on a countrywide count query. The data-pack builder (plan, phase 3) will report real numbers.

## H. Code health (what makes changes risky)

- **No safety net:** half the tests fail, the typecheck fails, and nothing runs either before deploy. A fix in one place can quietly break another.
- **Global state is mutated in place,** and refreshes are forced (`questionModified()`). Two pipelines (map refresh and hiding zones) share one global "loading" flag as a lock. That's the root of B4 and B20.
- **The question engine isn't pure:** it reads global state and pops toasts from inside the maths, so it can't be unit-tested or moved off the UI thread as-is.
- **Very large files:** ZoneSidebar (1.4k lines), TutorialDialog (1.2k, embeds real question cards), OptionDrawers (860), and two copy-pasted 800-line sidebar components.
- **Dead or odd files:** `src/pwa.ts` is never used. `src/styles/licenses/` is untracked by git (an Apache license file dated Feb 2026). Round-2 question 23 asks what it is.
